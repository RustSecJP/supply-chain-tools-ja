# パッケージレビュープルーフの作成 {#creating-package-review-proof}

パッケージレビュープルーフ (Package Review Proof) は、ソフトウェアパッケージのある
バージョン/リリースをレビューした結果を記録します。

## 責任 {#responsibility}

レビューが正直であることが重要です。最低限、`thoroughness` と `understanding` を
正しく調整してください。

ほかのユーザは、あなたが提供した情報を使って、ソフトウェアの品質と信頼性を
判断するかもしれません。

あなたのプルーフは暗号学的に署名され、エコシステムの中で流通します。
`crev` システムを使うことに明示的にも暗黙的にも法的な責任は伴いませんが、
ほかの人はほぼ確実に、それを使ってあなたやあなたのほかの仕事などを評価するでしょう。

プルーフを作って公開することで、あなたはほかの人がそれを自由に使うことに
暗黙のうちに同意したことになります。

## データフィールド {#data-fields}

- `review` - クレートの特定のバージョンのレビュー。すべてのフィールドが `none`
  の場合は、レビューが行われなかったことを意味する。セクション全体を削除しても
  同じ効果になる
  - `digest` - プロジェクトの内容全体の再帰的なダイジェスト
  - `thoroughness` - レビューにかけた時間と労力
    - `high` - 長く、深く、集中したレビュー。正式なセキュリティレビューの
      一部であることもある。「1 ファイルあたり 1 時間以上」
    - `medium` - 標準的で、集中した、それなりの深さのコードレビュー。「1 ファイルあたり
      約 15 分」
    - `low` - 軽いレビュー。「1 ファイルあたり約 2 分」
    - `none` - レビューなし、またはざっと目を通しただけ。「1 ファイルあたり数秒」。
      信頼できるプロジェクトや評判の良いプロジェクトの場合や、問題を警告するために
      プルーフを作る場合には、それでも役に立つ
  - `understanding`
    - `high` - 完全に理解している
    - `medium` - よく理解している
    - `low` - 一部がよくわからない
    - `none` - 理解できていない
  - `rating`
    - `strong` - あらゆる点で安全で良く、どんな用途にも向いている
    - `positive` - 安全で使って問題ない。小さな問題はあるかもしれない
    - `neutral` - 安全だが欠陥がある
    - `negative` - 深刻な欠陥があり、本番での利用には向かない
    - `dangerous` - 使うのは危険。深刻な欠陥があり、さらに/または悪意がある可能性がある
- `advisories` - アドバイザリは、重要な修正を含むパッケージのバージョンを示す
  （リスト）
  - `ids` - 修正されるイシューを識別する ID のリスト
  - `range` - 影響を受ける可能性のあるバージョン
    - `all` - それより前のすべてのバージョン
    - `major` - 同じメジャーリリースバージョンの中の、それより前のすべてのバージョン
    - `minor` - 同じマイナーリリースバージョンの中の、それより前のすべてのバージョン
  - `severity`
    - `high` - 致命的なイシュー（多くの場合セキュリティに関わる）
    - `medium` - 重要
    - `low` - 深刻度が低い
- `issues` - イシューは、リリースにある問題を報告する（リスト）
  - `id` - イシューの ID
  - `severity` - `advisories` セクションと同じ
- `alternatives` - 似た、またはより良い代替の候補。`name` が空のリストの要素は
  自動的に無視され、削除される
- `flags` - 追加のフラグ
  - `unmaintained` - パッケージがメンテナンスされていないか、放棄されている。**注意**: ほかの
    ほとんどのデータフィールドと違い、このフラグは今のバージョンだけでなく
    パッケージ全体に適用される
- `comment` - このレビューについての人間が読める情報（たとえば、なぜ行ったか、
  どのように行ったか、`rating` の説明）
- `override` - 対象のパッケージについて、レビューを上書きする（無視する）Id の
   リスト

# その他の情報 {#other-information}

新しいプルーフは古いプルーフを上書きします。
