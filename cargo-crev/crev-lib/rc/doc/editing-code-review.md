# コードレビュープルーフの作成 {#creating-code-review-proof}

コードレビュープルーフ (Code Review Proof) は、ソフトウェアプロジェクトをファイルごとに
レビューした結果を記録します。

## 責任 {#responsibility}

レビューが正直であることが重要です。最低限、`thoroughness` と `understanding` を
正しく調整してください。

ほかのユーザは、あなたが提供した情報を使って、ソフトウェアの品質と信頼性を
判断するかもしれません。

あなたのプルーフは暗号学的に署名され、エコシステムの中で流通します。
`crev` システムを使うことに明示的にも暗黙的にも法的な責任は伴いませんが、
ほかの人はほぼ確実に、それを使ってあなたやあなたのほかの仕事などを評価するでしょう。

## データフィールド {#data-fields}

- `date` - プルーフのタイムスタンプ
- `from` - プルーフの作者
- `review` - レビューの詳細
  - `revision` - レビュー時点でのリビジョン管理システムのチェックサム
  - `digest` - プロジェクトの内容全体の再帰的なダイジェスト
  - `thoroughness` - レビューにかけた時間と労力
    - `high` - 長く、深く、集中したレビュー。正式なセキュリティレビューの
      一部であることもある。「1 ファイルあたり 1 時間以上」
    - `medium` - 標準的で、集中した、それなりの深さのコードレビュー。「1 ファイルあたり
      約 15 分」
    - `low` - 軽いレビュー。「1 ファイルあたり約 2 分」
    - `none` - レビューなし、またはざっと目を通しただけ。「1 ファイルあたり数秒」。
      信頼できるプロジェクトや評判の良いプロジェクトの場合や、問題を警告するために
      プルーフを作る場合には、それでも役に立つ
  - `understanding`
    - `high` - 完全に理解している
    - `medium` - よく理解している
    - `low` - 一部がよくわからない
    - `none` - 理解できていない
  - `rating`
    - `strong` - あらゆる点で安全で良く、どんな用途にも向いている
    - `positive` - 安全で使って問題ない。小さな問題はあるかもしれない
    - `neutral` - 安全だが欠陥がある
    - `negative` - 深刻な欠陥があり、本番での利用には向かない
    - `dangerous` - 使うのは危険。深刻な欠陥があり、さらに/または悪意がある可能性がある
- `comment` - このレビューについての人間が読める情報（たとえば、なぜ行ったか、
  どのように行ったか、`rating` の説明）
- `files` - レビューしたファイルのリスト
