# 組織や企業で使う {#using-in-organizations-and-businesses}

`cargo-crev` は、チーム、グループ、企業、さらには非常に大きな組織をサポートすることを
明確な目標として開発されています。オープンソースのコードを使ってソフトウェアを開発する
企業には、取り込むオープンソースのコードの完全性と信頼性を確かめるという重要な
ニーズがある、と私たちは考えています。

そう考えているので、`crev` を使うことに関心のあるグループには、意見やニーズを
伝えてもらうようお願いしています。そうすれば、できるだけ早く対応できます。
そうしたグループにとって `cargo-crev` を役に立つものにすることで、
活気のあるコードレビューのエコシステムを素早く立ち上げられることを願っています。

このドキュメントでは、ソフトウェア組織で `cargo-crev` を活用する方法について、
全体的な構想を説明します。`cargo-crev` についての一般的な知識があると役に立つので、
先に [入門ガイド](getting_started.html) を読んでおいてください。

## 概要 {#overview}

組織で `cargo-crev` を活用するには、次の手順に従います:

まず、組織のための信頼の網 (Web of Trust) を作る必要があります。WoT はルートアイデンティティから
始まり、それによって定義されます。つまりこの手順では、ルートアイデンティティを安全に作り、
その WoT をどのように作って長期にわたって維持していくかを決めます。

次に、組織のメンバが生成した *プルーフ* を保存し、流通させる方法を確立する必要があります。
これはふつう、1 つ以上の git リポジトリを用意することを意味します。

ここまで来たら、メンバは依存のレビューとレビュープルーフの作成を始められます。

最後の手順は、コードレビューのポリシーを自動で強制することです。たとえば
CI パイプラインで行います。

## ルートアイデンティティ {#root-identity}

ルートアイデンティティを作るときは、セキュリティを考慮することが重要です。
そのため、信頼できるコンピュータ上で、組織の信頼できるメンバ（たとえばセキュリティ担当者）が
作ることを推奨します。このアイデンティティの秘密鍵は、適切に保管して守るよう
注意しなければなりません。

この ID の目的は、 として働くことで、ふつうは受動的にだけ使われます。

ルートアイデンティティは、ふつう組織全体の信頼の起点として受動的に使われます。
能動的に使われるのは、新しい *信頼プルーフ* に署名するとき、つまり
組織の中で使われるほかのアイデンティティを追加する（または削除する）ときだけです。

個々の貢献者が使うアイデンティティは、本人が作って管理できます。作ったあとで、
組織の WoT に含めてもらうために提出できます。

非常に大きな組織の場合は、特定のグループやチームが管理する中間アイデンティティを
置いた、アイデンティティの階層を作ることもできます。これにより、アイデンティティに署名する
作業を分散でき、ルートアイデンティティをオフラインで安全に保つのにも役立ちます。

## プルーフの管理 {#proof-management}

組織の中のすべてのアイデンティティで、共有の git リポジトリを 1 つ使えます。
あるいは、各個人が自分の git リポジトリを使ってレビューを公開することもできます。

コードレビューのポリシーに応じて、個々の貢献者が作ったプルーフは、内部向けにも、
公開にもできます。コードレビューをより広いコミュニティと共有することは、
セキュリティに意識的に取り組んでいることの証明になり、コミュニティへの
恩返しの一つの形にもなります。

## コードレビューのポリシーを強制する {#enforcing-code-review-policy}

`cargo-crev` は、任意のアイデンティティの視点から依存の信頼を検証する機能を実装しています。

``` text
cargo crev crate verify --for-id <rootID>
```

は、`rootID` の視点からすべてのパッケージのレビュー状態を検証する基本的な方法です。
これは各開発者がローカルで使えます。CI パイプラインの一部として設定することも
できます。返される終了コードが検証の状態を示します。

ほかの設定オプションで、検証を通るのに必要な正確な条件を定義できます。
必要なレビューの数、最低限の徹底度などです。
