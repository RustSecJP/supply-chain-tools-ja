# アドバイザリ（とイシュー）の報告 {#reporting-advisories-and-issues}

`crev`（したがって `cargo-crev` も）には、イシューとアドバイザリの報告のサポートがあります。

イシューもアドバイザリも、*パッケージレビュープルーフ* の省略可能な一部です。
そのため、常に特定のクレートのバージョンと結びついていて、
少し独特な動き方をします

## イシュー {#issues}

`cargo crev report` を使うと、クレートの特定のリリースにあるイシューを報告できます。

各イシューには ID が付きます。ID は任意の文字列にできます。
`CVE-xxxx-xxxx` や `RUSTSEC-xxxx-xxxx` のような識別子を推奨しますが、
それがない場合は代わりに URL を使えます。

クレートのバージョンに結びついたイシューは、その特定のリリースが影響を受けることを
述べているだけです。それが必ずしも影響を受ける最初の、あるいは唯一のバージョンで
あるとは限りません。

また、イシューは報告された最初のバージョンから未解決として扱われます。`crev` は、
`id` が一致する *アドバイザリ* が見つかるまで、それ以降のすべてのバージョンも
影響を受けるとみなします。

**ふつうは、イシューではなく *アドバイザリ* を報告するほうがよいです**。イシューが
最も役に立つのは、修正されたリリースがまだないときです。その場合、まだ存在しない
バージョンに結びついたアドバイザリは作れないからです。

## アドバイザリ {#advisories}

`cargo crev advise` を使うと、アドバイザリを含む *パッケージレビュープルーフ* を作れます。

アドバイザリは、それ以前に影響を受けていたある範囲のバージョンについて、
問題を修正した最初のバージョンで報告するべきです。

簡単にするために、影響を受けるバージョンの範囲は 1 つの `range` フィールドで指定します。

たとえば: ある問題が 1.4.0 以降のすべてのリリースに影響し、修正がバージョン 1.4.5 で
リリースされた場合、マイナーリリース全体（アドバイザリを含むリリースより前の、
1.4.x に一致するすべてのバージョン）が影響を受けたので、`range: minor` とします。

これで範囲の指定は簡単になりますが、常に正確とは限りません。もし問題がバージョン
1.4.1 で初めて入り込んだのなら、バージョン 1.4.0 も誤って影響を受けることになります。
ですが、これはまれで、範囲を広めにとりすぎても問題にはなりません。

場合によっては、同じアドバイザリを複数のバージョンについて作る必要があるかもしれません。
たとえば、影響を受けた複数のメジャーバージョンについて、パッチを当てたバージョンが
提供された場合です。
