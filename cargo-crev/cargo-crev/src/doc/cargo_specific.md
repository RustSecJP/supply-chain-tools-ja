# Cargo 固有の機能 {#cargo-specific-features}

`crev` は、言語やエコシステムに依存しない、コードレビューのためのシステムです。
かなり汎用的ですが、各エコシステムで利用できる特定の機能やデータとの統合を
禁じたり妨げたりはしません。むしろ逆で、エコシステムごとによく統合されたツールを
作ることは `crev` の構想の一部です。
`cargo-crev` はまさに、Rust 言語と `cargo` パッケージマネージャのための
そうしたツールです。

そのため `cargo-crev` は、`cargo` のユーザを助けるための機能を複数実装しています。

## 既知のオーナー {#known-owners}

理想的な世界なら、誰もが使っているコードを自分でレビューし、さらに/または
ほかの評判の良いレビュアに頼るだけで済みます。ですが、採用が臨界量に達するまでは、
それは難しい目標です。

この問題に対処するために、`cargo-crev` では、クレートの作者の評判によって
クレートの信頼性を判断できます。

crev のアイデンティティはそれぞれ「既知のオーナー」のリストを作って管理できます。編集するには `cargo
crev repo edit known` コマンドを使います。各行は crates.io のユーザ名かグループ名で、
それはある程度信頼できるとみなされます。

依存の検証のときに `--skip-known-owners` 引数を使うと、既知のオーナーが少なくとも
1 人いるクレートを飛ばせます。

セキュリティ上の影響を考えることが重要です。crates.io や、評判の良いクレートの作者の
個人アカウントが侵害されることはありえます。また、クレートのオーナーが作者のリストに
載っているからといって、ほかの共同作者も信頼できるとは限りません。

ですから、この機能は明らかに妥協の産物です。ですが、おそらく問題ない依存を
除外するのにはとても役に立ちます。そうした依存は、評判のあまりない出どころのコードを
先にレビューしたあとでレビューできます。

## ダウンロード数 {#download-counters}

`cargo crev crate verify` は、クレートの人気の簡単な目安として、そのクレートの特定の
バージョンのダウンロード数と、クレート全体のダウンロード数の両方を表示します。
ダウンロード数が特に少ないクレートやバージョンは、深刻なバグや悪意のあるコードを
持ち込むリスクが高くなります。

## Geiger カウント {#geiger-count}

[`geiger`](https://crates.io/crates/geiger) は、`unsafe` なコードの行数を数える
バイナリ兼ライブラリです。`cargo-crev` はこれを使って、各依存の *geiger カウント* を
表示します。`unsafe` なコードはメモリ安全性の問題を持ち込むことがあるので、
geiger カウントが 0 でないことは、そのコードを優先してレビューする十分な理由になります。

## コードの行数 {#lines-of-code}

`cargo-crev` は [`tokei`](https://crates.io/crates/tokei) を使って、各依存が持ち込む
Rust のコードの総量を計算します。小さなクレートは、すぐにレビューするのに良い候補です
（すぐ済むからです）。大きなクレートは、多くの場合もっと小さな代替に置き換えられます。
